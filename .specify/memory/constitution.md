# Quick Remote Toolkit Constitution

## I. Текущая сессия и защита данных
Все действия выполняются от текущей Windows-сессии. Не запрашивать, сохранять или
передавать пароли без отдельного согласованного решения безопасного хранения.
Не включать реальные клиентские CSV, персональные данные и секреты в Git/примеры.
Текст отправленных сообщений не сохранять в журнале или настройках.

## II. Совместимость и узкий эффект операций
Сохранять CSV number;computer;ip;person, UTF-8/Windows-1251, JSON-контракт и прежний
AppData-путь. Сохранять неизвестные поля, backup и защиту повреждённого JSON.
Использовать штатные инструменты Windows; ввод проверять и передавать как данные.
Не обходить права SMB/WinRM/WTS. Удаление членства не удаляет учётную запись.
Изменённые команды проверять ручным эквивалентом только на разрешённых тестовых ПК.

## III. Единственная реализация — Rust
Поддерживается только src/QuickRemoteToolkit.Rust: Windows x64 MSVC, egui/eframe.
Не добавлять зависимость от прежней реализации или .NET Desktop Runtime.
WPF/C++-прототипы хранятся только в истории Git. Пользователь принял Rust UI
2026-11-17; историческая попиксельная эквивалентность не является новым release gate.
Изменения UI должны сохранять читаемость, обе темы, привычные сценарии и доступность.

## IV. Отзывчивость и достоверность результатов
Блокирующие операции выполнять вне UI-потока; контролировать повторный запуск,
устаревшие ответы и тайм-ауты. Старт процесса не означает успех удалённого действия.
Тайм-аут изменения удалённого состояния может означать неизвестный результат.
Не отмечать непроведённые проверки как успешные; mocks и сборка не доказывают сеть.

## V. Проверяемая сборка и выпуск
Cargo.lock обязателен. Форматирование, clippy без предупреждений, тесты, Windows
release-сборка и упаковка должны пройти перед выпуском; точные команды — AGENTS.md/README.
Cargo.toml — источник версии; UI/Windows metadata/поставка должны совпадать.
Публиковать тег на проверенный main после применимых GitHub checks/review.
Не перемещать опубликованные теги, не обходить защиту веток. Поставка не включается в Git.

## Процесс и управление
Для существенных работ Spec Kit: требования → план → задачи → реализация → проверка.
Небольшие исправления допускаются без новой спецификации. Исторические спецификации
сохраняются с обозначением контекста; незавершённые проверки не закрываются задним числом.
AGENTS.md содержит практические правила, README — команды и инструкции пользователю.

Поправки принимаются сопровождающим проекта. Влияние 2.0.0→3.0.0: по прямому решению
пользователя от 2026-11-17 отменено сохранение WPF/прототипа в актуальном дереве;
правила безопасности/совместимости и честности проверок сохранены. Финализация и
новый релиз отражены в specs/006-rust-release; старые открытые проверки остаются историей.
