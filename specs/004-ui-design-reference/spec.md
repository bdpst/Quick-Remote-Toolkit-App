# Feature Specification: Эталон интерфейса для переноса

**Feature Branch**: `codex/rust-rewrite`
**Created**: 2026-11-16
**Status**: Ready
**Input**: Документировать существующий интерфейс main без изменения приложения.

## User Scenarios & Testing
### User Story 1 - Воспроизведение интерфейса (Priority: P1)
Разработчик получает точное описание трёх окон, тем, компонентов и поведения.
**Why this priority**: Устраняет догадки при переносе.
**Independent Test**: Найти размеры, подписи и поведение каждого окна по гайду и источникам.
**Acceptance Scenarios**:
1. Given правило оформления, When прочитан гайд, Then доступны значение, источник и уровень подтверждения.
2. Given отличие веток, When выбран эталон, Then оно выделено отдельно и не становится новым требованием.

### User Story 2 - Использование токенов (Priority: P2)
Разработчик читает цвета и размеры из машиночитаемого документа.
**Why this priority**: Предотвращает ошибки ручного переноса.
**Independent Test**: Разобрать токены и сопоставить обе палитры с эталоном.
**Acceptance Scenarios**:
1. Given тема, When прочитаны токены, Then доступны все её именованные цвета и единицы размеров.

### User Story 3 - Проверка соответствия (Priority: P2)
Проверяющий получает сценарии сравнения будущего интерфейса.
**Why this priority**: Делает воспроизведение проверяемым.
**Independent Test**: Найти сценарий каждого окна, темы и существенного состояния.
**Acceptance Scenarios**:
1. Given непроверенное состояние, When открыт чеклист, Then оно явно обозначено и не выдано за наблюдение.

### Edge Cases
Отсутствующий CSV, пустая выборка, длинные значения, ошибочный ввод, отсутствие прав, тайм-аут, несколько мониторов, разные DPI; отсутствие безопасного запуска не блокирует анализ исходников.

## Requirements
### Functional Requirements
- **FR-001**: Зафиксировать SHA main, актуальность origin и отличия рабочей ветки, сохранив изменения пользователя.
- **FR-002**: Описать все три окна, компоненты, размеры, типографику и обе темы с источниками существенных правил.
- **FR-003**: Описать таблицу, поиск, CSV, команды, журнал, валидацию диалогов, клавиатуру и предпочтения.
- **FR-004**: Предоставить все цветовые токены и повторяющиеся размеры с единицами в валидном машиночитаемом файле.
- **FR-005**: Дать матрицу и чеклист всех окон и тем; разделить запуск, код и непроверенное. Сохранить реальные снимки, если доступны.
- **FR-006**: Пройти спецификацию, план, задачи, выполнение и анализ согласованности без изменения приложения и существующих спецификаций.
### Key Entities
Эталон (ветка, версия, доказательства); правило (значение, источник, подтверждение); токен (имя, тема, единица); сценарий (условия, действие, результат).

## Success Criteria
### Measurable Outcomes
- **SC-001**: Описаны 3 из 3 окон и 2 из 2 тем; у существенных правил есть источники.
- **SC-002**: Все цветовые ресурсы обеих тем присутствуют в разбираемом файле токенов.
- **SC-003**: Каждое FR покрыто задачей и проверкой; непроверенные визуальные состояния обозначены.

## Assumptions
Фиксируются текущие особенности, включая недостатки. Исправления и реализация переноса исключены. Удалённые операции на рабочих компьютерах запрещены для снимков. Гайд не заменяет спецификацию переноса.
