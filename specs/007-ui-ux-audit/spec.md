# Feature Specification: Аудит интерфейса и актуальный дизайн-гайдлайн

**Feature Branch**: `codex/007-ui-ux-audit`
**Created**: 2026-11-19
**Status**: Ready for planning
**Input**: Аудит актуального интерфейса, обновление принятого гайдлайна без изменения приложения.

## User Scenarios & Testing

### User Story 1 - Доказательный аудит (Priority: P1)
Сопровождающий получает воспроизводимые находки и честную границу проверок перед доработкой.
**Why this priority**: Ошибка выбора цели или интерпретации результата влияет на работу администратора.
**Independent Test**: Для каждой находки доступны источник, шаги, влияние и критерий приёмки.
**Acceptance Scenarios**:
1. Given актуальный main, When аудит выполнен, Then указан коммит и результаты проверок обеих тем.
2. Given недоступная проверка, When сформирован отчёт, Then она явно отделена от подтверждённых результатов.

### User Story 2 - Единые принятые правила (Priority: P2)
Разработчик находит правила таблицы, действий, журнала, диалогов и клавиатуры в существующем гайдлайне.
**Why this priority**: Предотвращает расхождения следующих изменений с принятым интерфейсом.
**Independent Test**: По гайдлайну можно определить размеры, темы, состояния и источник значений.
**Acceptance Scenarios**:
1. Given предлагаемое улучшение, When прочитан гайд, Then оно не выдано за действующее правило и находится в аудите.
2. Given фирменные элементы, When документация обновлена, Then монитор с шестерёнкой сохранён.

### Edge Cases
Пустой CSV, отсутствие результатов, длинные значения, минимальное окно, ошибки ввода, ожидание и неизвестный результат по тайм-ауту; физический DPI, который невозможно проверить, явно обозначается.

## Requirements

### Functional Requirements
- **FR-001**: Отчёт MUST указывать исходный коммит, окружение, размеры, темы и фактически проверенные масштабы.
- **FR-002**: Каждая находка MUST иметь ID, приоритет, экран, источник, шаги, факт, влияние, исправление и критерий приёмки.
- **FR-003**: Матрица MUST охватывать импорт/обновление, поиск, выбор, избранное, колонки, копирование, меню, действия, splitter, экспорт и диалоги.
- **FR-004**: Гайд MUST описывать обе темы, текст, отступы, окна, таблицу, кнопки, подсказки, журнал, фокус и ошибки; источники значений должны быть названы.
- **FR-005**: Работа MUST сохранять пользовательские данные и использовать только тестовые примеры; изменения ограничены документацией и материалами задачи.
- **FR-006**: Отчёт MUST отличать запуск инструмента, подтверждённый и неизвестный результат; гипотезы и непроверенные сценарии перечисляются отдельно.

### Key Entities
- Находка: ID, доказательство, воспроизведение, влияние, приоритет, предлагаемое исправление, приёмка.
- Проверка: сценарий, тема, размер, масштаб, результат, ограничение.

## Success Criteria

### Measurable Outcomes
- **SC-001**: 100% находок имеют все поля FR-002.
- **SC-002**: 100% сценариев FR-003 имеют статус выполнено, частично либо не выполнено с причиной.
- **SC-003**: Один обновлённый гайд покрывает все категории FR-004; ни одна гипотеза не названа подтверждённой.
- **SC-004**: В итоговом diff отсутствуют изменения программы и реальные клиентские данные.

## Assumptions
- Аудит не меняет сценарии и не реализует предложенные исправления.
- Работа в текущей Windows-сессии; удалённые операции на рабочих ПК исключены.
- Синтетические состояния доказывают отображение, но не сетевой результат.
