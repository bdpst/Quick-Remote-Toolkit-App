# Feature Specification: Полный паритет Rust с main
**Feature Branch**: codex/rust-rewrite
**Created**: 2026-11-16
**Status**: Ready
**Input**: Закончить перенос, сохранив код и изменения пользователя.
## User Scenarios & Testing
### User Story 1 — Данные и выбор цели (Priority: P1)
Оператор использует прежние CSV/settings, поиск, избранное и таблицу без потери данных.
**Why this priority**: Без правильной цели поддержка невозможна.
**Independent Test**: Обезличенные CSV UTF-8/1251 и WPF JSON дают прежние значения после сохранения/перезапуска.
**Acceptance Scenarios**: Given WPF favorite key, When загрузка/restart, Then отметка и фильтр сохранены. Given поиск по домену, When ввод, Then строки найдены. Given отсортированная таблица, When команда, Then цель соответствует выбранной строке.
### User Story 2 — Windows операции (Priority: P1)
Полный набор команд, ICMP/домен, SMB, WTS сообщения и управление членством работают отзывчиво.
**Why this priority**: Основное назначение.
**Independent Test**: Подменяемые адаптеры проверяют адресацию, ошибки, timeout и параллелизм без рабочих ПК.
**Acceptance Scenarios**: Given длительная операция, When поиск/закрытие, Then UI не зависает и поздние события безопасны. Given admin timeout, Then неизвестный результат без автоматического повтора.
### User Story 3 — UI и поставка (Priority: P1)
Оператор получает воспроизводимый Rust executable с эталонными окнами, журналом, темами и клавиатурой.
**Why this priority**: Рабочий перенос включает представление и доставку.
**Independent Test**: Cargo-проверки и отдельная portable-поставка, UI-матрица P01–P16.
**Acceptance Scenarios**: Given журнал, When очистка, Then нет старых записей/подтверждения. Given новая сборка, When запуск без .NET, Then приложение работает.
### Edge Cases
Пустой/повреждённый ввод, дубликаты, отказ записи, кириллица/кавычки/метасимволы, недоступная сеть, несколько сеансов, DPI, закрытие во время фоновой операции.
## Requirements
### Functional Requirements
- FR-001: Полный контракт CSV/настроек main, атомарная запись settings.json, обратная совместимость WPF и резервная копия при миграции.
- FR-002: Поиск по 4 полям, избранное/нормализация/fallback/дубликаты/rollback, выбор/сортировка/копирование/ПКМ/doubleclick/Ctrl+F.
- FR-003: Все Windows-команды, одиночный и массовый ICMP, таймаут/лимит, домен/рабочая группа, SMB текущего пользователя.
- FR-004: WTS сообщения и PowerShell членство по SID со всеми ограничениями/ответами/ошибками; без текста сообщений в журнале.
- FR-005: UI по гайдлайну SHA 91689516c96d52877bba3480bf498b7d807ead64: 3 окна/2 темы/все состояния, журнал/очистка/TXT/CSV.
- FR-006: Безопасные команды/FFI, фоновые адаптеры, защита повторов и поздних событий, автоматические тесты без рабочих ПК.
- FR-007: Cargo fmt/clippy/test/release, воспроизводимый Windows CI/архив/publish-rust, README/runtime-зависимости, рабочий WPF сохранён.
- FR-008: Матрица ID→сценарий→source→контракт→Rust→проверка→статус и краткий progress; все намеренные отличия объявлены.
### Key Entities
Client, Settings, Log, Operation/Event, Reference, ParityScenario — как в эталоне; фоновое событие должно относиться к своей загрузке данных.
## Success Criteria
### Measurable Outcomes
- SC-001: 100% строк матрицы реализованы и имеют доказательство проверки; неподтверждённое не отмечено завершённым.
- SC-002: Все Cargo-проверки на Windows успешны без предупреждений собственного кода.
- SC-003: Все P01–P16 в обеих темах проверены либо имеют точный внешний блокер; полный паритет при блокерах не заявляется.
- SC-004: Старый JSON и CSV читаются без потерь, поставка запускается без .NET.
## Assumptions
Новые требования этого документа уточняют прежнюю specs/002, исторический текст не переписывается. Отдельный settings-rust.json из прототипа больше не является контрактом: общий settings.json разрешён запросом. Преднамеренные улучшения безопасности и экранирование CSV фиксируются в матрице. Реальные удалённые изменения — только явно разрешённые цели.
